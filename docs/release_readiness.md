# Divergence Project History and Public Release Readiness

**Snapshot as of 26 November 2026.** This covers the Divergence-specific work through `main` at `37e5642d2f`, 587 commits after the standalone baseline and 102 commits after the source used for the friend preview. It summarizes changes by player-facing system. The changelog and generated species reports carry the individual changes.

**Feature completion comes first.** Three buildable districts still use their inherited outdoor layouts: Home Base, Market and Trial Area. The Park has an intentional outdoor conversion. The rebuilt Main Hall, Labs and Safari still connect to older interiors, some of which need an explicit release decision. Finish the player-facing feature backlog below before freezing the public candidate.

### Recommended implementation order

1. **Use Market as the next map conversion.** Its bank, crafting and restaurant functions are clear, and the shared assets and hallway conventions already exist.
2. **Plan Home Base before drawing the new layout.** The decoration region, layer rules and style choices make this more than a tileset swap. Commit to a player-facing model for customisation before rebuilding the grounds and floors.
3. **Finish Trial Area as one feature.** Pair its room and service redesign with the first-clear handoff and Trial rules disclosure. That closes the most significant postgame flow still split across old and new interfaces.
4. **Walk every wing and return.** Close PokéConnect's public scope, sweep inherited interiors and directions, then play the game from new save through first Trial. Freeze the candidate once those player-facing flows are coherent.

| July | Made Fast Path standard, expanded generated Uniques and added Anomalous Abilities, introduced more run modifiers and Legendary encounters, revised Safari, Trials, Ride Training, and gimmick restrictions, and disabled legacy multiplayer. | Much of the single-player battle and run identity that defines today's game. |
| August | Unified run creation, expanded seeded route events, Treasure rooms, Battle Towers, Adventure Path visuals and generated content tooling. Froze the private **Preview** on 19 August using ROM source `dc65cec08d`. | A playable friend milestone with recorded smoke checks and a packaged artifact. The setup sheet identifies the exact ROM source. |
| September | Reconciled the 650-decision rebalance, implemented Ascension, added dedicated den and start rooms, rebuilt the underground base and services, and revised new-game flow around the portal and Safari. | The current campaign structure, postgame difficulty ladder and authored hub. The Preview predates these changes. |
| October | Revised Ascension's nature/IV progression and moved trainer AI difficulty to a role-based model. | A0 uses random natures, A1 neutralizes them, and competitive nature thresholds are A2/A6/A11. ## Work required before going live

### 1. Freeze the release scope and restore reproducibility

- [ ] Review the three corridor sources, include them in the candidate, and confirm that a clean checkout can generate the matching includes and build. Check the first subsequent failure, if any, after dependency generation succeeds.
- [ ] Pick a public version and artifact target. Follow the project's major-version rule if compatibility with the tagged baseline is treated as a released save promise. The July preview checklist floated `DIV-v0.2.0`, but the save break needs an explicit version decision before adopting it.
- [ ] Decide the fresh-save or migration policy, supported emulator target, and scope of support for Rogue Assistant/Extended Storage. If advertised, verify it on the candidate. Keep disabled PokéConnect multiplayer clearly labelled in game and in release notes.
- [ ] Freeze additional feature, map and balance work once the candidate enters validation. Resolve known dead ends, misleading prompts, progression failures and major battle defects as candidate fixes.

### 2. Establish current automated and build evidence

- [ ] On the exact candidate SHA, pass Linux debug and release builds, the full split-suite validation, and the macOS build. Record per-suite results and any existing known failures. Use the split launcher rather than the monolithic test ELF.
- [ ] Run the complete rebalance check, species/baked-data verification, and offline profile verification with the cache pinned to the source lock. Run the authored-hub checks and onboarding route validator for the final maps. The latest static passes can be recorded against this snapshot and repeated after any relevant source change.
- [ ] Build the exact distribution ROM from a fresh checkout with the release launcher. Record toolchain, commit, ROM size, EWRAM/IWRAM usage and SHA-256. Verify the build leaves the source tree clean.
